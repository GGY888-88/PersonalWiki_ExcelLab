# PersonalWiki ExcelLab 4.6.4 測試指南

## 1. 測試目的
確認 4.6.3 之後仍偏上的三個主畫面輸入欄位已透過複合控制項置中，同時不影響原生單行輸入行為、搜尋、複製、提示文字、300% DPI 按鈕排列及其他原本正常的輸入欄位。

## 2. 自動靜態測試
在解壓後的 `PersonalWiki_ExcelLab` 根目錄執行：

```powershell
python scripts/test-4.6.4-input-alignment.py
python scripts/run-4.6.4-python-tests.py
```

第一個命令檢查這次改動契約、三個欄位範圍、內層單行 TextBox、事件／屬性轉送、BAT 編碼及按鈕／DPI 保留條件。第二個命令再執行歷史 DPI、工具列、表格、視窗工作區、4.6.1 UI 及 4.6.0 acceptance contract 回歸。

## 3. Windows 建置

```powershell
dotnet build PersonalWiki.Desktop/PersonalWiki.Desktop.csproj -c Release
```

或雙擊 `01_建置程式.bat`。建置記錄位於 `build_release.log`。建置成功後可使用 `02_啟動程式.bat`；也可使用 `03_建置並啟動.bat`。

## 4. 主畫面三個欄位驗收
請在 100%、150%、200%、300% DPI 各檢查一次；至少在 300% DPI 使用者原先回報的環境重現：

1. 資料庫路徑：文字實際內容上下留白應大致相等；欄位仍為唯讀；雙擊後仍可全選並複製完整路徑。
2. 全文搜尋：未輸入時提示文字應置中；輸入中文、英文、數字後文字應置中；焦點取得／失去後均檢查；按 Enter 仍執行搜尋，不應插入換行。
3. 標籤：未輸入時「標籤」提示應置中；輸入既有標籤後文字置中；搜尋交集行為不變。
4. 視窗最大化／還原及跨螢幕 DPI 變更後，三欄位置不得累積偏移。
5. 主功能按鈕仍使用既有 80×22 設定；300% DPI 下每顆按鈕完整顯示並依既有規則換行。

建議在同一 Windows 環境保留 100% 及 300% 兩張同畫面截圖，以便精確比較文字上下留白。

## 5. 非目標欄位保護檢查
以下欄位本版刻意沒有換成複合控制項，僅確認原有行為沒有回歸：

- 類型、封存狀態、排序下拉選單。
- 日期起迄核取方塊與 DateTimePicker。
- 圖片頁「篩選檔名或圖片說明」。
- 標籤管理重新命名輸入框。
- 條目名稱、類型輸入框。
- 多行摘要及筆記編輯區。

此清單若出現偏上或裁切，先提供欄位截圖及 DPI；除非已確認問題，不要連帶替換這些控制項。

## 6. 測試素材與資料安全
- 測試資料庫：`samples/PersonalWiki_3.6.0_Test.db`。
- 若需要進行會寫入資料的測試，先複製到暫存目錄；不得使用正式資料庫直接試驗。
- 本版未要求執行正式 Excel 匯入。若自行驗收匯入，只使用測試資料庫副本及新的備份路徑。

## 7. 通過標準／未完成項目
- Python 靜態與歷史回歸全部通過。
- Windows .NET 10 編譯需為 0 errors；warnings 應為 0，若有警告需列出，不得以全域 NoWarn 隱藏。
- 100%／150%／200%／300% 畫面中的三個目標欄位均須通過；其他欄位、80×22 按鈕尺寸及完整換行排列不得回歸。
- 如果文字仍偏上，請提供同欄位 100%／300% 截圖、Windows 版本、螢幕縮放比例及程式讀取到的 `DeviceDpi`。不要先改字體大小或增加外層欄位高度。
- 目前交付環境沒有 .NET SDK／Windows，故編譯與實機驗收狀態為「待 Windows 驗收」。
