# PersonalWiki ExcelLab 4.7.0 後續開發計畫

## 開發原則
4.7.0 不以重做主畫面或更新資料層為目標。先穩定 4.6.6，再把下一批「彼此獨立、可單獨驗收」的功能集中開發。沒有使用者確認的功能不提前寫入程式，不更動已完成且正常的區域。

## 階段 1：完成 4.6.6 Windows 驗收
- Windows .NET 10 編譯，記錄完整 build log，確認錯誤 0、警告 0。
- 100%／150%／200%／300% 檢查資料庫路徑、全文搜尋、標籤三欄的輸入文字及 PlaceholderText。
- 確認資料庫唯讀／雙擊複製、Enter 搜尋、標籤交集搜尋正常。
- 確認 80×22 主功能按鈕設定、300% 完整換行、日期／ComboBox／列表／Excel 預覽未回歸。
- 若三個輸入框高度仍不合適，只修正資料庫路徑、全文搜尋、標籤，不一次改所有輸入框。

## 階段 2：整理 UI 控制項清冊與回歸矩陣
- 記錄主畫面、圖片頁、標籤管理、條目新增／編輯、Excel 精靈中的 TextBox、ComboBox、DateTimePicker 類型與目前用途。
- 把「單行輸入」、「提示文字」、「唯讀」、「可複製」、「多行輸入」分別測試；避免把多行欄位轉成單行，或把其他正常欄位套用同一個控制項。
- 建立 100%／150%／200%／300% 實機測試紀錄；未確認有問題的欄位只觀察、不修改。

## 階段 3：下一批獨立功能（待確認需求後集中開發）
- 先收集明確功能需求，再按「互不依賴、可單獨測試」分組，一批完成後再做整合測試。
- 每個功能附測試素材、成功／失敗案例及對應操作文件。
- 優先使用現有服務及 Schema；新增資料表／欄位、變更資料路徑、匯入流程或設定格式，都必須先取得使用者明確同意。
- 不把 UI 置中修正與資料層新功能混在同一個難以回退的修改中。

## 階段 4：4.7.0 發行交接
- 開發 → 自我檢查 → Windows 建置 → 測試 → 打包 → 更新交接文件 → ZIP CRC／SHA-256 驗證。
- 每版根目錄保留 `01_建置程式.bat`、`02_啟動程式.bat`、`03_建置並啟動.bat`。
- 解壓後根資料夾維持 `PersonalWiki_ExcelLab`，不附版本號。
- 交接文件包括版本歷史、下一版本、ZIP、Schema、套件、專案結構、測試狀態、未解問題及完整續開發指令。

## 不變更清單
本輪三框高度微調已完成，等待使用者畫面確認。未經同意，不修改已完成的搜尋／查詢、安全匯入、備份／還原、SQLite Schema、Models、Services、CLI、資料路徑、桌面設定路徑、NuGet 版本及目前 80×22 主功能按鈕設定。
