# 4.6.3 輸入框垂直置中與 BAT 相容性測試指南

## 測試環境
- Windows 10／11 繁體中文環境。
- .NET 10 SDK。
- Python 3。
- 優先使用先前回報的 Windows 300% DPI 設定；另檢查 100%、150%、200%。

## 自動靜態回歸
在解壓後的 `PersonalWiki_ExcelLab` 根目錄執行：

```powershell
python scripts/run-4.6.3-python-tests.py
```

單獨檢查本版變更：

```powershell
python scripts/test-4.6.3-input-alignment.py
```

## .NET 編譯

```powershell
dotnet build PersonalWiki.Desktop/PersonalWiki.Desktop.csproj -c Release
```

或雙擊 `01_建置程式.bat`。建置全文記錄寫入 `build_release.log`；建置失敗時 BAT 會以記事本開啟記錄，不會將整份日誌直接灌入 CMD。

## 單行文字垂直置中驗收
1. 啟動程式，開啟測試資料庫。確認主畫面「資料庫」路徑欄位中的路徑文字與欄位上下留白大致相同。
2. 在「全文搜尋」輸入中文、英文及數字，分別檢查未輸入時提示文字、輸入後文字、取得焦點時游標與選取文字的位置。
3. 在「標籤」欄位輸入既有標籤，檢查提示文字及實際輸入文字的垂直位置。
4. 清除全文搜尋及標籤，再重複檢查提示文字是否仍居中；避免只確認有文字時的狀態。
5. 切換主視窗大小、最大化／還原，以及從 100%／200% 切到 300% DPI 後重新開啟程式，確認對齊不會逐次向上或向下漂移。
6. 按 Enter 執行全文搜尋；確認不會插入換行，搜尋行為與前版相同。
7. 圖片頁「篩選檔名或圖片說明」、標籤管理的重新命名輸入框、新增／編輯條目的名稱與類型欄位也確認維持原生單行 TextBox；多行摘要及筆記仍可輸入換行，不可被改成單行。

## BAT／編碼驗收
1. 將解壓後的 `PersonalWiki_ExcelLab` 放在包含繁體中文的路徑下，再雙擊 `01_建置程式.bat`。
2. CMD 應只顯示英文 ASCII 狀態訊息，不應出現亂碼；建置完成後應保留 `build_release.log`。
3. 建置失敗時確認 `build_release.log` 由記事本開啟，且 CMD 視窗停留在錯誤狀態，不應瞬間關閉。
4. 雙擊 `02_啟動程式.bat`，應啟動既有 Release 輸出；沒有建置輸出時應顯示明確錯誤並保留視窗。
5. 雙擊 `03_建置並啟動.bat`，應一次完成建置及啟動，不要求建置與啟動之間額外按鍵。

## 300% DPI 按鈕與既有功能驗收
- 確認目前主功能按鈕尺寸設定仍為使用者先前設定的 80×22（96 DPI 基準），未被本版重設。
- 確認主功能按鈕仍以完整按鈕為單位換行，不出現右側按鈕被截斷。
- 確認日期篩選、排序、搜尋、清除、分頁、清單欄寬、圖片篩選、標籤管理與 Excel 預覽仍可操作。
- 本輪不需執行 Excel 正式匯入；若要測試匯入，請只使用測試資料庫副本及新的備份檔路徑。

## 測試素材
- SQLite 測試資料庫：`samples/PersonalWiki_3.6.0_Test.db`（執行可能寫入的測試前先複製到暫存資料夾）。
- 歷史 Python／SQLite fixture 與測試工具：`samples/`、`scripts/`。
- 本版靜態測試：`scripts/test-4.6.3-input-alignment.py`。

## 通過標準與限制
- 自動靜態回歸須全部通過。
- `dotnet build` 必須在 Windows／.NET 10 SDK 實際完成，且編譯錯誤 0、警告 0（若有分析器警告，請先記錄，不得用全域 NoWarn 隱藏）。
- 上述靜態測試不能取代原生 EDIT 提示文字與 300% DPI 畫面的實機檢查；若提示文字仍偏上，請提供 100% 與 300% 的同畫面截圖、Windows 版本及實際 DeviceDpi。
