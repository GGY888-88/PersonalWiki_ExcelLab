# PersonalWiki ExcelLab 4.6.2 更新說明

## 修正重點

### 1. Windows DPI 感知
- Desktop WinForms 專案設定 `ApplicationHighDpiMode=PerMonitorV2`。
- 程式碼建立的主要表單明確使用 96 DPI 基準及 `AutoScaleMode.Dpi`。
- DPI 切換後重新檢查表單尺寸，並將視窗限制在目前螢幕的可用工作區內。
- 對 300% 等高於本次主要驗收範圍的比例，若設計尺寸大於工作區，視窗會縮至工作區，內容以捲動方式保留操作入口。

### 2. 主畫面
- 資料庫路徑欄位移至搜尋列前段；完整路徑仍可選取、複製及水平檢視。
- 主功能列可水平捲動；主篩選區改為兩列固定分組：第一列為資料庫、全文搜尋、類型、封存狀態與標籤；第二列為建立日期起迄、更新日期起迄及排序。標籤與輸入框維持固定組合，不會被換行拆開；每列必要時獨立水平捲動。
- 全文搜尋、下拉欄位及按鈕依字型實際高度調整；搜尋／清除／分頁按鈕置於篩選區下方的獨立第四列（第一列為主功能按鈕、第二／三列為篩選條件）；四列高度分別依 DPI 與實際控制項高度計算。
- 主視窗最小尺寸會依可用工作區調整，不再以固定大尺寸阻止視窗縮小。

### 3. Excel 匯入精靈
- 第 1 步預覽、第 2 步欄位用途、第 3 步資料安全檢查全部切換為 DPI 自動縮放。
- 300% 實測回報的全文搜尋輸入框、筆記／圖片操作按鈕文字裁切，改用目前 DPI 與字型度量調整高度；筆記、圖片、標籤及來源工具列依內容自動加高。
- Excel 第 1 步預覽表格改用自動資料列高度、儲存格文字換行與自動重新計算列高，避免固定 30px 列高裁切預覽文字。
- 說明標籤依所在內容區寬度換行。
- 第 2 步資料列設定標籤與輸入框改為自動排版；狹窄視窗可換行，不再依賴固定 44／48 像素列高。
- 確認／取消按鈕採自動尺寸及可換行按鈕列；表格維持 Dock Fill 並可水平／垂直捲動。
- 第 3 步檢查項目依實際寬度重新計算核取方塊高度，長標籤可換行。

### 4. 相容性與資料安全
- 保留 4.6.1 既有桌面功能及 Excel 匯入流程；未修改 Services、Excel mapping／preflight／transaction／import service。
- 未修改 SQLite Schema、資料庫路徑、桌面設定路徑或 NuGet 套件版本。
- 原始 Excel 唯讀、匯入前備份與驗證、單一交易等既有保護流程保持不變。

## 版本
- CLI 與 Desktop 專案版本同步為 4.6.2。


## 300% 日期篩選重疊修正（後續 Hotfix）
- 日期條件不再使用 `DateTimePicker.ShowCheckBox` 的內嵌核取方塊。
- 新增獨立的「啟用日期篩選」核取方塊，與日期選擇器分開排列、保留間距及明確寬度。
- 日期篩選仍提供相同的 `Checked`／`Value` 行為；未勾選時不套用日期條件，查詢／資料庫邏輯不變。
- 在表單初次顯示及 DPI 變更後重新計算核取方塊與日期欄位尺寸。
- 僅修改 Desktop UI；不修改 `Services/`、Models、CLI、SQLite Schema 或 Excel 匯入邏輯。


## .NET 10 WinForms 建置修正（WFO1000）
- `DateFilterControl.Checked` 與 `DateFilterControl.Value` 是執行期間的查詢狀態，不是 Visual Studio 設計器要寫入表單初始化程式碼的設計期屬性。
- 兩項屬性加入 `DesignerSerializationVisibility(DesignerSerializationVisibility.Hidden)`，明確禁止設計器序列化這些執行期狀態，修正 .NET 10 的 WFO1000。
- 不使用全域 `NoWarn` 或停用分析器；日期核取／取消及 `yyyy-MM-dd` 查詢值行為不變。

## 300% 表格欄寬與空間利用修正（最新 UI Hotfix）
- 主畫面左側搜尋結果清單及右側「相關條目」清單改為依目前可用 client width 與欄位權重動態分配欄寬；視窗／SplitContainer 尺寸改變及 DPI 切換後重新配置。
- 為名稱、摘要、日期、狀態、相關條目及共用標籤欄設定 DPI 感知的可讀最小寬度；空間不足時保留欄位最小寬度並允許 ListView 水平捲動，不將所有欄位壓成不可讀的窄欄。
- Excel 第 1 步待匯入預覽表格改用 Fill 欄寬模式填滿可用表格寬度；欄位填滿比例參考欄名及預覽樣本文字寬度，並設定最小欄寬；長文字仍透過換行及自動列高顯示。
- 僅修改 `PersonalWiki.Desktop/MainForm.cs`、`PersonalWiki.Desktop/ImportDialogs.cs`、測試及文件；資料庫、Models、CLI、Excel mapping／preflight／transaction／import services 均未修改。


## 300% 視窗剩餘空間利用修正（最新畫面回饋）
- 主畫面篩選列由單一長橫列改為兩列明確分組，避免更新日期條件超出右側可視範圍；不依賴整組自動換行，標籤與輸入格仍由固定 Panel 成組定位。
- 第一列包含資料庫、全文搜尋、類型、封存狀態及標籤；第二列包含建立日期起迄、更新日期起迄及排序；搜尋／清除／分頁按鈕位於獨立第四列，與兩列篩選條件分開計算高度。
- Excel 匯入第 1 步預覽表格原先 Dock Fill 已填滿高度，但 DataGridView 未使用資料列區域的預設背景色是灰色，容易誤認為表格高度不足；現在將表格背景與儲存格背景設為 SystemColors.Window，空白資料區仍可視為表格工作區，不再留下大片灰塊。
- 僅調整 Desktop UI 與靜態測試／文件；日期控制項、查詢條件語義、資料庫及 Excel 匯入流程不變。


## 300% 篩選列垂直間距與操作列可見性修正（最新回饋）
- 移除巢狀 `TableLayoutPanel` 內兩列各佔 50% 高度的配置，改由主畫面最外層配置四個獨立列：主功能按鈕、一般篩選、日期／排序篩選、搜尋／清除／分頁操作。
- 每列依實際控制項高度及水平捲軸狀態獨立計算，不再將兩列篩選內容分配到一個固定高度容器，減少兩列之間不必要的垂直空白，並確保查詢操作列有自己的可見高度。主功能列及查詢操作列在視窗寬度變更時也會重新量測，若水平捲軸出現會預留其高度。
- 左側搜尋結果 ListView 欄寬配置保留小幅 DPI 感知內縮，避免欄寬總和恰好等於 client width 時，仍因原生邊框／主題量測產生 1–2px 水平捲軸。若可用寬度不足以容納欄位最小寬度，仍允許水平捲動。
- 本輪僅修改 `PersonalWiki.Desktop/MainForm.cs`、靜態測試及文件；服務層、Models、CLI、日期控制項、Excel 預覽及匯入流程均未改動。


## 最新 300% 主功能按鈕換行與結果清單欄寬修正
- 主功能按鈕列不再顯示水平捲動；依實際可用寬度以完整按鈕為單位分列，確保右側批次封存、圖片完整性、重複圖片、資料庫健康及備份功能可被看到。
- 主畫面上方仍由單一像素配置器量測主功能列、一般篩選列、日期／排序列與搜尋／分頁列，避免不同 WinForms 自動縮放機制互相覆蓋。
- 搜尋結果與相關條目欄寬改為先配置全部欄位的可讀最小寬度，再依權重分配剩餘可用寬度；只有可用寬度小於最小欄寬總和時才會出現水平捲動，消除逐欄 `Math.Max` 累積超寬的情形。
- 啟動時狀態列的「上次使用資料庫」只是路徑提示，不代表已連線；按「開啟上次資料庫」或「開啟資料庫」才會實際載入資料與搜尋結果。此為既有啟動行為，本次沒有更改資料庫載入流程。
- 本輪僅修改 `PersonalWiki.Desktop/MainForm.cs`、靜態測試與文件；`Services/`、Models、CLI、DateFilterControl、SQLite Schema 及 Excel mapping／匯入流程未修改。
