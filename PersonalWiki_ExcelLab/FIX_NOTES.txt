PersonalWiki ExcelLab 4.6.2 - Main Toolbar Wrap and List Width Fix

本次修正（依 300% DPI 最新畫面回饋）：
1. 主功能按鈕列不再使用水平捲動；依視窗可用寬度將完整按鈕換至下一列，避免右側批次封存、圖片檢查及資料庫檢查功能被裁切。
2. 主畫面上方仍使用單一像素配置器計算主功能列、一般篩選列、日期／排序列及搜尋／分頁操作列的實際高度，避免混用 TableLayoutPanel 自動列高與手動像素列高。
3. 搜尋結果清單欄寬演算法改為先配置各欄可讀最小寬度，再按權重分配剩餘空間；僅當面板寬度小於全部欄位最小寬度總和時才保留水平捲動，避免逐欄套用最小寬度後累積出多餘寬度。
4. 保留日期篩選獨立核取方塊／日期選擇器、搜尋操作列與既有按鈕事件。
5. 更新靜態回歸測試，使其驗證按鈕完整換行與最小欄寬優先分配，不再檢查已撤除的舊 TableLayoutPanel 列高實作。

資料庫載入說明：
- 啟動時狀態列顯示「上次使用資料庫」僅表示記錄了上次路徑，不代表資料庫已開啟。
- 要載入資料，請按主功能列的「開啟上次資料庫」或「開啟資料庫」；開啟成功後程式才會執行搜尋並填入左側結果清單。

保留：
- DateFilterControl、WFO1000 設計器序列化標記與日期查詢語義。
- 資料庫 Schema、Models、CLI、Services、Excel 欄位 mapping、預檢及匯入交易流程。
- Excel 預覽 Fill 欄寬、文字換行、自動列高與白色工作區。

驗證限制：
- 本執行環境沒有 .NET SDK／Windows，未能執行實際 dotnet build 或 Windows 300% DPI 實機測試。
- Python 靜態回歸套件已執行成功；4.6.0 查詢驗收腳本中的 0/1 是故障路徑自我測試的預期輸出，35 項查詢契約檢查通過，但不代表已跑過完整正式資料庫案例。
- 請在 Windows 端執行 dotnet build，並按「開啟上次資料庫」後驗收資料列、按鈕換行及左側欄寬。
